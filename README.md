# ODS YAML <-> Excel Редактор (`ods_yaml_editor.xlsm`)

Инструмент на чистом VBA для чтения, табличного редактирования, валидации и полной синхронизации конфигурационных YAML-файлов таблиц ODS по схеме `config/schema_ods_table.json`.

## Состав проекта

- `ods_yaml_editor.xlsm` — готовая к работе книга Excel с настроенным листом `ODS_Config`, кнопками управления, выпадающими списками, подсказками, защитой от случайной перезаписи в Git и встроенными макросами.
- `.gitignore` — исключает временные lock-файлы Excel (`~$*.xlsm`, `*.tmp`) из индекса Git.
- `vba/` — исходный код макросов (6 компактных модулей `.bas` < 26 КБ и 2 модуля книги/листа `.cls` в кодировке `Windows-1251` для прямого импорта в редактор VBA `Alt + F11` -> `File -> Import File...`):
  - `ThisWorkbook.cls` — автообновление при открытии и защита файла `.xlsm` от случайного сохранения (`Workbook_BeforeSave` / `Workbook_BeforeClose`) для работы в общем Git-репозитории без конфликтов.
  - `Sheet1.cls` — обработка смены схемы в выпадающем списке ячейки `B2`.
  - `modYamlCodec.bas` — чтение и запись файлов в `UTF-8` без BOM и парсер YAML (включая блочные SQL `|-` и массивы).
  - `modYamlWriter.bas` — сериализация в стандартный YAML (`key: value`) и общие скалярные/лексические функции.
  - `modOdsValidator.bas` — проверка данных обеих таблиц по правилам `schema_ods_table.json` (обязательные поля, типы, правило `if/then/else` для `watermark` при `full` vs `incremental`/`snapshot`, типы колонок и `decimal(p,s)`).
  - `modOdsManager.bas` — основные макросы кнопок: выбор папки `config`, загрузка схем, полная синхронизация с YAML и макрос администратора `UnlockWorkbookSaveOnce`.
  - `modOdsUI.bas` — отрисовка обеих таблиц на листе `ODS_Config` друг под другом, чтение данных с листа и оформление панели управления.
  - `modOdsHelpers.bas` — макросы добавления/удаления строк, проверки схемы и вспомогательные утилиты работы с листами и относительными путями (`.\config`).

## Как пользоваться

1. Откройте `ods_yaml_editor.xlsm` в Microsoft Excel и нажмите **«Включить содержимое»** (разрешить выполнение макросов).
2. В верхней закреплённой панели (строки `1–3`):
   - **Папка config (`B1`)**: автоматически определяется как `<папка книги>\config` (можно выбрать любую другую папку кнопкой **«Папка config...»**).
   - **Схема (`B2`)**: выберите нужную папку схемы из выпадающего списка (кнопка **«Обновить схемы»** пересканирует подпапки в `config`).
   - Нажмите **«Загрузить из YAML»** (или подтвердите загрузку при смене схемы в ячейке `B2`).
3. На листе `ODS_Config` друг под другом отображаются две умные таблицы Excel:
   - **1. ТАБЛИЦЫ СХЕМЫ (`tblTables`)** — по одной строке на каждый `.yml` файл в папке схемы (все разделы кроме `columns`: корневые поля, `source`, `capture`, `watermark`, `table`).
   - **2. КОЛОНКИ ТАБЛИЦ (`tblColumns`)** — все колонки раздела `columns` всех таблиц схемы (связь по первому столбцу `table_name`).
4. Редактирование:
   - Для добавления/удаления таблиц используйте кнопки **`+ Таблица`** и **`- Таблица`** на верхней панели — макрос аккуратно вставляет/удаляет строки со сдвигом нижней таблицы и подставляет значения по умолчанию.
   - Для добавления/удаления колонок используйте кнопки **`+ Колонка`** и **`- Колонка`** (при выделенной строке таблицы поле `table_name` заполняется автоматически).
   - Многострочные SQL-выражения в ячейках вводятся через `Alt + Enter`.
   - Если в поле `cross_join_lateral_selects_trino` нужно задать несколько элементов массива SQL, разделяйте их отдельной строкой `---`.
   - Пустые ячейки для nullable-полей (`schedule_cron`, `*_clause_trino`, `select_wm_*`, `export_ahd_gp` и др.) при сохранении записываются как `null`, а пустые комментарии (`comment`) — как `''`.
5. Проверка и сохранение:
   - Кнопка **«Проверить схему»** проверяет обе таблицы по всем правилам `schema_ods_table.json` без записи на диск.
   - Кнопка **«Сохранить в YAML»** выполняет **полную синхронизацию** выбранной папки схемы:
     - создаёт новые `<table_name>.yml` для добавленных таблиц;
     - обновляет изменённые `.yml` в формате стандартного YAML (`key: value`, `UTF-8` без BOM);
     - если строка таблицы была удалена из Excel, запрашивает подтверждение со списком файлов и удаляет соответствующие `.yml` файлы с диска.

## Командная работа в Git без конфликтов

Файл `ods_yaml_editor.xlsm` защищён от локальных изменений из коробки без какой-либо настройки Git у разработчиков:

1. **Относительный путь `.\config`**: в ячейке `B1` хранится `.\config` (разрешается относительно папки, где открыт `ods_yaml_editor.xlsm`), а локальные абсолютные пути из метаданных книги удалены — книга одинаково работает на любом компьютере сразу после `git clone` / `git pull`.
2. **Перехват `Ctrl + S` (`Workbook_BeforeSave`)**: обычное сохранение книги блокируется (`Cancel = True`), поэтому бинарный `.xlsm` на диске **не перезаписывается** и не попадает в `git status`. Вместо этого Excel предлагает сразу записать изменения в YAML-файлы (**«Сохранить в YAML»**).
3. **Чистое закрытие (`Workbook_BeforeClose`)**:
   - после открытия книги, загрузки схемы и сохранения в YAML выставляется `ThisWorkbook.Saved = True`, поэтому Excel закрывается без лишних вопросов и без записи в `.xlsm`;
   - если на листе остались несохранённые в YAML правки, при закрытии появится диалог **«Сохранить изменения в YAML-файлы перед выходом?»** (`Да` — синхронизирует YAML и закроет книгу; `Нет` — закроет книгу без изменения `.xlsm`; `Отмена` — вернёт к редактированию).
4. **Как обновить сам шаблон `.xlsm` (для мейнтейнера)**: если вы поменяли дизайн листа или код VBA и хотите намеренно сохранить `ods_yaml_editor.xlsm` для коммита в Git, нажмите `Alt + F8`, запустите макрос `UnlockWorkbookSaveOnce` и затем нажмите `Ctrl + S` (разрешение действует ровно на одно сохранение).
